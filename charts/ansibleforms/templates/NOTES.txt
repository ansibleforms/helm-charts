An AnsibleForms Runner (an RTE on its own, {{ dig "rte" "image" "" (.Values.containers | default dict) }}) is installed
as {{ .Release.Name }} in namespace {{ .Release.Namespace }}. It runs no app, no database and no ingress.

Where it dials

  It dials the app at {{ include "ansibleforms.runner.appUrl" . }} and keeps one WebSocket open to it
  (RTE_MODE=outbound), joining as the runner "{{ $runnerName }}". Nothing has to reach it: it needs only
  its way out to the app's address, through HTTPS_PROXY if you set one in applications.rte.env.
{{- if not (hasPrefix "https://" (include "ansibleforms.runner.appUrl" .)) }}
  An http:// address: the socket and its token go in clear. Use the app's https address outside the cluster.
{{- else if not (has (toString (dig "appTlsVerify" true (.Values.runner | default dict))) (list "false" "0")) }}
  The app's certificate is checked: name a private CA with NODE_EXTRA_CA_CERTS in applications.rte.env.
{{- else }}
  runner.appTlsVerify is false: it accepts any certificate the app shows. Inside one trusted network only.
{{- end }}

    kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "ansibleforms.runner.fullname" . }} -f

  "dialing the app at ..." then "connected to the app" say it got there. The pod is Ready once
  the app has welcomed it on the socket.

How it gets approved
{{ if $joinToken }}
  It presents the join token from runner.joinToken on its first start, so the app approves it at
  once and adds the runner "{{ $runnerName }}". From then on it signs in with its own token, kept in
  the Secret below: the join token may expire or be revoked without affecting it.
{{- else }}
  No runner.joinToken, so it asks to join and waits for an admin: in the app, under
  Connections > Runners, approve "{{ $runnerName }}" (the bell in the header counts the runners waiting).
  Its log shows the token's fingerprint, to compare with the one the app shows before approving.
  For an unattended install, make a join token under Connections > Runners and pass it as
  runner.joinToken.
{{- end }}

Seeing it in the app

  Connections > Runners lists "{{ $runnerName }}", type RTE, mode outbound, connected while its socket is
  open. Forms run on it with runner: {{ $runnerName }}, or tick it as the default runner.

Its token

  It signs in to the app with the RTE_TOKEN in:

    kubectl -n {{ .Release.Namespace }} get secret {{ include "ansibleforms.rte.tokenSecretName" . }} -o jsonpath='{.data.{{ include "ansibleforms.rte.tokenSecretKey" . }}}' | base64 -d

  Keep that Secret: the app knows the runner by it. A new token is refused until an admin approves
  the runner again.

Checking it works

  helm test {{ .Release.Name }} --namespace {{ .Release.Namespace }}

  checks that the app at {{ include "ansibleforms.runner.appUrl" . }} answers from this namespace.

  Those credentials came from your values file, which means they are also in

  put them in a Secret you manage and point secrets.existingSecret at it.
{{ else if dig "generate" false (.Values.secrets | default dict) }}
  The chart made these up on the first install and reads them back on every
  upgrade afterwards, so they do not change. They exist nowhere but in that
  Secret: back it up, or you will be resetting the admin password and losing
  every credential AnsibleForms has encrypted.
{{ end }}
{{- $enc := toString (dig "server" "env" "ENCRYPTION_SECRET" "" (.Values.applications | default dict)) }}
{{- if and $enc (ne $enc "<ENTER_SECRET_HERE>") (ne (len $enc) 32) }}
About ENCRYPTION_SECRET
{{ if lt (len $enc) 32 }}
  Yours is {{ len $enc }} characters. AnsibleForms uses it directly as an
  aes-256 key, so it pads anything shorter to 32 with a constant that is in its
  own source code: {{ sub 32 (len $enc) }} of those 32 bytes are public knowledge.
{{- else }}
  Yours is {{ len $enc }} characters. AnsibleForms cuts it to 32 before using it
  as an aes-256 key, so the last {{ sub (len $enc) 32 }} never count for anything.
{{- end }}
  Worth fixing on a new install. Worth thinking twice about on an old one: it is
  the key stored credentials are encrypted with, and changing it does not fail,
  it just quietly turns them into rubbish. Take a backup and re-enter them.
{{ end }}

Running playbooks

  Playbooks run on the RTE in the server pod ({{ dig "rte" "image" "" (.Values.containers | default dict) }}).
  The app dials it on {{ include "ansibleforms.rte.url" . }} and keeps one WebSocket open (inbound).
{{- if eq (include "ansibleforms.rte.seedEnabled" .) "true" }}
  The chart registered it as the default runner, "{{ dig "rte" "runnerName" "rte" (.Values.containers | default dict) }}", under Connections > Runners.
{{- else }}
  Add it under Connections > Runners: type RTE, mode inbound, with an RTE credential of
  Connections > Credentials holding the address {{ include "ansibleforms.rte.url" . }} and the token from:

    kubectl -n {{ .Release.Namespace }} get secret {{ include "ansibleforms.rte.tokenSecretName" . }} -o jsonpath='{.data.{{ include "ansibleforms.rte.tokenSecretKey" . }}}' | base64 -d
{{- if eq (include "ansibleforms.rte.userSeed" .) "true" }}

  CONFIG_SEED_PATH points at a seed of your own: you can declare it there instead:

    credentials:
      items:
        - name: rte
          credential_type: rte
          url: {{ include "ansibleforms.rte.url" . }}
          password: ${RTE_TOKEN}
    runners:
      items:
        - name: rte
          type: rte
          rte_mode: inbound
          credential: rte
          is_default: true
{{- end }}
{{- end }}
